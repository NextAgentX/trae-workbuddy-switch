# Buddy Switch 交互架构重构方案

> 状态：**方案稿，未动代码**。本文只做信息架构（IA）与交互设计决策，不含实现。
> 依据：Material Design 3（导航 / 应用栏 / 组件行为）+ Nielsen 十大可用性原则 + ISO 9241-110 对话原则。
> 结论摘要见第 0 节，待你拍板的决策见第 7 节。

---

## 0. 结论先行

**把「产品 × 区域」合并成一个顶层概念——作用域（Scope），从侧栏搬到顶部应用栏；侧栏退化为只承载 5 个任务的固定导航；页面内只保留页面自己的视图参数。**

一句话原则：**一个维度，只在一个层级，以一种形态，出现一次。**

三个可度量的收益：

| 指标 | 现状 | 目标 |
|:---|:---|:---|
| 跨数据域任务的切换步数（例：从「WorkBuddy 国内版·账号」到「Trae 国际版·本周 Token」） | 4 次点击，且**顺序不可交换**（必须先选产品、再选区域） | 3 次点击，顺序自由 |
| 作用域状态容器 | 3 套互不通信（组件 state / 各页 localStorage / URL 查询参数） | 1 套（URL 为唯一真值） |
| 侧栏产品名截断风险 | 存在（源码注释记录：195px 内容区放不下 `WorkBuddy`） | 消除（作用域名迁入顶部横向空间） |

需要诚实说明的边界：这不是「数量级」的步数优化（4→3）。**主要收益在一致性、状态正确性与认知负担**，而不是点击数。跨数据域是低频动作，但「切了区域却在另一个页面看不到」是一类**静默错误**——它不报错，只会让用户做出错误判断。

## 1. 现状诊断（逐条对应源码）

### 1.1 维度盘点

| 维度 | 取值 | 当前载体 | 状态归属 |
|:---|:---|:---|:---|
| 产品 | `workbuddy` / `trae` | 侧栏顶部 `ProductSwitch` | URL path（`/` vs `/trae/`） |
| WorkBuddy 区域 | `cn` / `global` | 账号页内两行大 Tab（`RegionTab`） | 组件内 `useState`，默认 `cn`，**离开页面即丢** |
| WorkBuddy 统计范围 | `cn` / `global` / `all` | 各统计页 `RegionBar` | 各页**独立** localStorage（`TokenStatsPage` 注释明写「不与账号管理页联动」） |
| Trae 区域 | `cn` / `global` | 账号页 `TraeVariantBar` | URL `?line=` |
| Trae 程序位 | `trae_work` / `trae_code` | 账号卡片上的按钮 | 操作处（**当前设计正确**） |
| 任务模块 | 账号 / Token / 积分 / API 服务 / 设置 | 侧栏 `NavLink` | URL path |
| 应用级设置 | — | 侧栏底部 `AppSettingsEntry` | 弹层 |
| 视图参数 | 时间范围 / 数据来源 / 分布维度 | 页面内多组 Tab | 页面内 state |

**4 个「作用域级」维度，散落在 4 个物理层级、3 种状态容器、3 种控件形态里。**

### 1.2 六个具体问题

1. **两级切换。** 换一个数据域需要「选产品 → 选区域」两次定位、两次点击，且两级控件在页面上的相对位置随页面变化。
2. **同一维度三种形态。** 账号页是「两行大 Tab + 状态圆点」，统计页是「单行 `RegionBar`」，Trae 是「`TraeVariantBar`」。违反 ISO 9241-110 的「一致性」与 Nielsen #4。
3. **状态不共享（最严重）。** 用户在账号页切到国际版，进入 Token 统计页看到的仍是国内版——因为前者是组件 state、后者读自己的 localStorage。这类错位**不报错、不提示**，是最难被发现的一类缺陷。
4. **侧栏整体换血。** 5 项导航随产品整体替换。虽有 `lastPathRef` 记住路径，但视觉上整条导航「跳变」，位置记忆失效。同时 220px 宽度已达承载极限。
5. **设置层级混乱。** 产品级设置是侧栏第 5 项（`SettingsPage` 1152 行、7 张功能卡、无二级导航）；应用级设置却在侧栏底部——而 MD3 明确把侧栏底部分配给应用信息区，不是导航项。
6. **控件密度过高。** `CreditStatsPage` 同屏存在「统计范围 / 趋势范围 / 模型分类范围 / 积分详情类型」四组切换器；`TokenStatsPage` 有「统计范围 / 数据来源 / 分布维度 / 概览范围」四组。全局维度与视图维度叠加在同一屏，用户无法一眼分清「哪个控件决定我看见什么」。

### 1.3 已经做对、必须保留的三件事

- **Trae 程序位下沉到账号卡片。** 它是「操作落到哪个客户端」，不是「我在哪套账号体系里」——语义判断正确，不要上移。
- **两个产品的任务结构 5:5 同构。** 这是「侧栏可以固定 5 项」的前提条件，也是本方案成立的基础。
- **区域 / 变体不写进侧栏。** 避免在侧栏凭空造出第二个产品层级。本方案是把它们迁到顶部，而不是塞回侧栏。

## 2. 设计原则（每条都对应到本方案的具体决策）

| 原则 | 出处 | 在本方案中的落实 |
|:---|:---|:---|
| 到达任一目的地 ≤ 2 次点击；顶层目的地 3–5 个 | MD3 Navigation | 侧栏固定 5 项，不再随产品变化 |
| 应用栏承载上下文与筛选；导航容器承载目的地 | MD3 Top app bar / Navigation drawer | 作用域上移顶部；侧栏只留目的地 |
| Hick 定律：决策时间随选项数与层级深度增长 | 公认准则 | 两级（产品→区域）合并为单层 4 项 |
| Fitts 定律：高频目标应大且位置稳定 | 公认准则 | 作用域选择器固定在顶部左一位置，全应用不移动 |
| 系统状态可见性 | Nielsen #1 | 当前作用域全程可见（顶部标签 + 状态圆点），不再依赖「记住自己切过什么」 |
| 一致性与标准 | Nielsen #4 / ISO 9241-110 | 同一维度统一形态、统一位置、统一状态容器 |
| 识别优于回忆 | Nielsen #6 | 作用域在顶部显式呈现，替代「用户要记得自己在哪个版本下」 |
| 用户控制与自由 | Nielsen #3 | 切换/删除等破坏性操作提供撤销（Snackbar + action），确认对话框只留给不可逆操作 |
| 错误预防 | Nielsen #5 | 消灭「区域静默错位」这类不报错的错误 |

## 3. 目标架构

### 3.1 三层模型

| 层 | 名称 | 内容 | 载体 | 是否全局 |
|:---|:---|:---|:---|:---|
| **L1** | 上下文（Context） | 作用域：`wb-cn` / `wb-global` / `trae-cn` / `trae-global` | 顶部应用栏 | 是，全应用唯一 |
| **L2** | 目的地（Destination） | 账号 / Token 统计 / 积分统计 / API 服务 / 设置 | 侧栏导航 | 是，5 项固定 |
| **L3** | 视图参数（View params） | 时间范围、数据来源、分布维度、合并开关、程序位 | 页面内参数条 / 卡片内按钮 | 否，页面私有 |

**为什么是「作用域」而不是「产品 + 区域」：**
四个组合各自拥有**独立的账号库、独立的认证文件、独立的配置**——它们互斥。用户的心智模型是「我现在管的是哪一套账号」，而不是「我选了哪个产品、再选了哪个版本」。把两个层级压成一个枚举，既符合 Hick 定律，也让「状态只有一个真值」成为可能。

**为什么 Trae 程序位不在 L1：** 区域决定「账号属于哪套体系」，程序位只决定「落到哪个客户端」。它是一个**操作参数**，留在操作处（账号卡片）是正确的。

### 3.3 组件映射（MD3 → 现有实现）

| 位置 | MD3 组件 | 落地方式 | 变更量 |
|:---|:---|:---|:---|
| 作用域选择器 | Menu button（应用栏内嵌） | 现有 `DropdownMenu` + 自定义 trigger（状态点 + 产品图标 + 名称 + 副标题） | 新增组件 |
| 侧栏 | Standard navigation drawer，280dp，5 项 | 现有 `<aside>` 由 220px 加宽至 280px；`navLinkClass` 补 MD3 state layer | 小 |
| 视图参数条 | Segmented button / Filter chip | 收敛为统一 `ViewParamBar`，替换现有散落的 `Tabs` / `role="tablist"` 手写块 | 中 |
| 程序位 | 卡片内 Button | 保留现状 | 无 |
| 破坏性操作反馈 | Snackbar with action（撤销） | 现有 `sonner` 补 action | 小 |
| 应用级设置 | 应用栏溢出菜单 | 现有 `AppSettingsEntry` 从侧栏底部迁至顶部 | 小 |

### 3.4 作用域选择器的形态（关键决策）

**用菜单按钮，不用 Segmented button 平铺。** 理由：

1. 四个作用域名（`WorkBuddy 国内版` / `WorkBuddy 国际版` / `TraeWork 国内版` / `TraeWork 国际版`）平铺会挤占整个应用栏，在 1200px 窗口下没有余量。
2. 菜单形态保留**并排视角**——打开即看到 4 个作用域各自的「已登录: xxx / 未登录 / 未检测到」状态。这是当前 `TraeVariantBar` 两行 Tab 的核心价值，不能丢。
3. 菜单是标准模式，用户零学习成本。

打开态结构（每项两行）：

```
● [图标] WorkBuddy 国内版      已登录: xxx@xx.com
○ [图标] WorkBuddy 国际版      未登录
● [图标] TraeWork 国内版       已登录: yyy
○ [图标] TraeWork 国际版       未检测到
```

**快捷方式（P4，加速器而非主导航）：** `Ctrl/Cmd + 1..4` 直接切作用域；`Ctrl/Cmd + K` 命令面板。命令面板**不替代**侧栏——MD3 与可发现性原则都要求主导航常驻可见。

### 3.5 状态与路由

单一真值：`scope ∈ { wb-cn, wb-global, trae-cn, trae-global }`。

```
/s/{scope}/{module}
例：/s/wb-global/token-stats
```

- **兼容策略：** `/` 与 `/trae/*` 全部 301 式重定向到 `/s/{上次或默认 scope}/*`；`?line=` 保留解析一次，之后写入新路由。旧书签不失效。
- **记忆：** 上次作用域写入 localStorage，冷启动时 `/` 直接落到它。
- **收益：** 刷新、前进/后退、分享链接行为一致；彻底消灭「账号页 state vs 统计页 localStorage」的分裂。

**与既有工程约定的冲突点（需提前确认）：** 本次改的是前端路由，不碰 `api.ts` 的 ROUTES 与后端命令名。但项目约定「`api.rs` 与 `commands.rs` 两条通道返回形状必须一致」——路由改造不触碰该约定；`npm run check:api` 只扫裸 `call("命令名")` 字面量，不受影响。

### 3.6 各页面改造要点

| 页面 | 现状 | 目标 |
|:---|:---|:---|
| 账号管理 | 页内区域 Tab（WorkBuddy）/ `TraeVariantBar`（Trae） | 区域 Tab 移除（已上移）；页头保留「当前作用域」只读标签 + 状态；账号卡片保留程序位按钮 |
| Token / 积分统计 | `RegionBar`（cn/global/all）+ 4 组视图参数 | `RegionBar` 移除；视图参数条首位放 **「范围：仅本作用域 / 合并全部」** 二态开关，默认「仅本作用域」 |
| API 服务 | 网关全局单例，Key 按 region 归属 | 作用域只影响 Key 的分组展示，页面不做全局作用域切换 |
| 设置（产品级） | 单页 1152 行、7 张卡、无二级导航 | 拆为二级导航（左 200dp 分段列表 + 右内容，或顶部 Tab + 锚点滚动同步）：自动签到 / 自动轮换 / 切换行为 / 版本账号 / 网关 / 计划任务 / 权限检查 |
| 应用级设置 | 侧栏底部入口 | 迁至应用栏溢出菜单 |

**关于「合并（all）」的说明：** `all` 是跨作用域聚合，无法由单一 scope 表达。把它降级为统计页内的二态开关，是保留能力的同时不把「区域」重新抬回全局层的唯一干净解法。

## 4. 分期落地（每期独立可验收，不推翻既有资产）

| 期 | 内容 | 验收标准 |
|:---|:---|:---|
| **P0** | 冻结维度词汇表；新增 `lib/scope.ts` 定义 4 个作用域与描述符；把「维度–载体」对照表写进项目记忆 | 词汇表评审通过，全项目统一术语 |
| **P1** | **治最痛**：建 `useScope()`，以 URL 为唯一真值 + localStorage 记忆。**不改布局**，让账号页 region、统计页 `RegionBar`、Trae `?line=` 全部读写同一个 scope | 从账号页切到国际版 → 进统计页仍是国际版 |
| **P2** | 改骨架：作用域选择器上移顶部；侧栏固定 5 项、加宽 280dp；路由换 `/s/{scope}/{module}` + 旧路由重定向 | 全部旧链接可达；侧栏不再随产品换血 |
| **P3** | 页面内收敛：`ViewParamBar` 统一；统计页「合并」开关；设置页二级导航；应用级设置归位 | 同一维度在所有页面同形同位 |
| **P4** | 加速器：快捷键、命令面板、撤销 Snackbar、空态与首次引导 | 高频任务 3 步内完成 |

**为什么 P1 必须先于 P2：** P1 只改状态容器、不动视觉，风险最低、收益最高（消灭静默错位）。若跳过 P1 直接做 P2，会同时引入「布局变更」与「状态变更」两个变量，回归时无法归因。

## 5. 验收度量

| 度量 | 方法 | 目标 |
|:---|:---|:---|
| 跨数据域任务步数 | 计点击数 | 4 → 3 |
| 作用域错位缺陷 | 手工回归：账号页切区域 → 逐个页面核对 | 归零 |
| 同一维度控件形态数 | 全页面扫描 `RegionBar` / `Tabs` / `role="tablist"` | 3 → 1（`ViewParamBar`） |
| 侧栏截断 | 各窗口宽度下 `scrollWidth == clientWidth` | 全部通过 |
| 设置页可寻址性 | 能否用一句话说清「自动轮换在哪」 | 二级导航项 ≤ 7，单层 |

## 6. 已否决的备选方案

| 方案 | 否决理由 |
|:---|:---|
| A. 保留侧栏产品 Tab，只统一区域控件 | 治标。两级切换、侧栏换血、220px 截断三个问题全部保留 |
| B. 侧栏三个顶级 Tab（WorkBuddy / Trae 国内 / Trae 国际） | 源码注释已实测：195px 内容区放不下三个标签。且把区域抬到与产品同级是**语义错误** |
| C. 以命令面板 / 全局搜索为主导航 | 牺牲可发现性。MD3 要求主导航常驻可见。只作为加速器保留 |
| D. 侧栏三级树（产品 → 区域 → 模块） | 220–280dp 不支持三级缩进；MD3 明确不推荐深层嵌套导航 |
| E. 每个产品独立窗口 / 工作区 | 成本过高，且违背「一个工具统一管理多套账号」的产品定位 |
| F. 作用域选择器用顶部 Segmented button 平铺 4 项 | 中文名称长度在 1200px 窗口下无余量，且不如菜单形态能承载并排状态 |

## 7. 需要你拍板的三个决策

1. **统计页的「合并（all）」** —— 保留为页内二态开关（推荐），还是提升为第 5 个作用域「全部」？
   - 推荐前者：合并是**视图**行为，不是数据域；提升它会让「当前登录账号」「签到」等账号类操作在「全部」下失去语义。
2. **Trae 程序位（TraeWork / TraeCode）** —— 是否在所有作用域下都保留「卡片上手动选」？还是国内版 / 国际版应有各自不同的默认程序位？
   - 此项与「Trae 区域轴尚未实现」的现状相关，若区域轴推进，需一并定默认策略。
3. **是否接受路由从 `/trae/accounts` 改为 `/s/{scope}/{module}`** —— 有旧链接兼容成本（一次性重定向即可覆盖），但换来状态单一真值。
